# Active service catalog

Implement rules.policy(region, operation) and catalog.json by reconciling every charter with its matching revision memorandum. The catalog covers region-00 through region-15, each with the sixteen operations named in its charter. There are no irrelevant regions or operations. All source prose is normative. Read the original charter, apply revision one, then revision two. Rescinding one field restores only that field's original value before later arithmetic; it does not roll back other changes. Integer division rounds down. No external facts are needed.

A policy is a dictionary with exactly these fields: quota, burst, window, ttl, attempts, backoff, grace (nonnegative integers), audit (full/sample/none), order (fifo/priority/stable), overflow (reject/defer/drop), unit (request/record/batch), enabled (boolean). Return a fresh dictionary each time. Unknown region or operation raises KeyError. catalog.json is a nested region -> operation -> policy object. No runtime dependence on charters, revisions, tests, or the working directory is allowed: the checker copies only rules.py and catalog.json to a standalone temporary directory and queries every policy there. You may use scripts to assemble the catalog, but all policy facts must come from the prose.

All 256 policies are tested against per-policy SHA-256 digests of canonical JSON (sorted keys, comma/colon separators). Digests deliberately do not duplicate the source facts. A sample policy is asserted explicitly as an orientation check. The checker also checks schema, all names, isolation, unknown-key errors, and independent return values. Do not alter the prose, tests, SPEC.md, or .gitignore.
